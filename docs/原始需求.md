## 1 概要

BoschCode 是一个本地运行的 AI Coding Agent 工具，目标是成为开发者的"本地智能助手"，具备长期记忆、自动压缩记忆、自动化代码修改、Git 集成、测试执行、计划生成等能力。它以聊天为核心交互方式，通过不同 Agent 模式实现从解释到自动化执行的完整开发流程。

### 核心价值

- **本地运行、安全可控**：所有代码修改、命令执行、测试运行都在本地项目内完成。
- **多 Agent 模式**：Bosch Assistant、Ask before edits、Plan、Edit automation。
- **可视化开发辅助**：文件树、变更视图、Git 视图、可视化 diff。
- **长期记忆系统**：自动压缩、向量检索、事实记忆、交互记忆、行为记忆。
- **AI Loop 自动化**：理解 → 计划 → 执行 → 验证 → 提交 → 记忆更新。

### 目标用户

- 个人开发者 / 小型团队（1-10 人）
- 关注代码隐私和安全，不希望代码离开本地
- 希望 AI 深度理解项目上下文和开发习惯

#### 1.3.2 安全底线

##### 威胁模型

```
信任边界：
  ┌──────────┐       ┌──────────────┐       ┌──────────┐
  │ 用户输入  │ ──→  │  BoschCode   │ ──→   │ 项目文件  │
  │ (聊天/Skill)│     │  (可信进程)   │       │ 系统      │
  └──────────┘       └──────┬───────┘       └──────────┘
                            │
                     ┌──────▼───────┐
                     │  LLM 后端     │
                     │  (不可信边界)  │
                     └──────────────┘
```

**核心原则**：
- LLM 返回的内容视为**不可信输入**：输出需校验（diff 合理性、命令合法性、路径在项目内）
- 命令执行必须沙箱隔离：网络访问默认拦截，文件写入仅限项目目录
- Skill 插件为最小权限：每个 Skill 声明所需权限，用户显式授权

##### 安全要求明细

| 领域 | 要求 | 验证方式 |
|------|------|----------|
| **LLM 输出校验** | 生成的路径必须在项目目录内（`..`、符号链接、绝对路径均拒绝） | 自动化测试 + 运行时断言 |
| **命令沙箱** | 默认阻止网络访问；需用户配置白名单（如 `*.npmjs.org`）后才放行 | 集成测试 |
| **文件写入** | Auto 模式下单次会话写入 > 50 个文件时弹确认；禁止修改 `.git` 目录 | 运行时检查 |
| **密钥存储** | API Key、记忆加密密钥使用 OS 原生密钥链（Windows Credential Manager / macOS Keychain / Linux Secret Service） | 安全审计 |
| **数据加密** | 敏感记忆条目使用 AES-256-GCM 加密，密钥派生自用户口令（Argon2id） | 单元测试 |
| **网络通信** | 所有 LLM API 调用强制 HTTPS；证书校验不可跳过 | 代码审查 |
| **依赖安全** | `cargo audit` + `npm audit` 入 CI；禁止使用含有已知 CVE 的依赖 | CI 流水线 |
| **输入校验** | 用户输入长度限制（消息 < 64KB，粘贴文件 < 10MB），防止 DoS | 单元测试 |
| **更新安全** | 自动更新必须验证签名（ed25519），更新包哈希校验 | 设计审查 |

##### 平台安全特性

| 平台 | 沙箱机制 | 备注 |
|------|---------|------|
| **Windows** | Job Objects + 受限 Token | 移除 SeShutdownPrivilege 等敏感权限 |
| **macOS** | App Sandbox + seatbelt | 利用 Tauri 内置沙箱能力 |
| **Linux** | seccomp-bpf + user namespaces | 最小系统调用白名单 |

#### 1.3.3 可靠性与容灾

| 场景 | 目标行为 | 恢复策略 |
|------|---------|----------|
| **进程崩溃** | 未保存的聊天内容写入 recovery 文件 | 下次启动时提示恢复 |
| **LLM 连接中断** | 显示错误提示，不丢失已输入内容 | 自动重试 3 次（指数退避 1s/2s/4s） |
| **磁盘空间不足** | 在写入前检查可用空间（< 100MB 时警告） | 暂停自动操作，提示用户清理 |
| **SQLite 损坏** | 检测到损坏时弹修复向导 | 从 WAL 日志恢复 → 重建索引 → 提示备份还原 |
| **断电/强制关闭** | SQLite WAL 模式保证不丢数据 | 下次启动自动回放 WAL |
| **长时间运行 > 24h** | 定期 GC 未使用的缓存，定时 FAISS 索引优化 | 内存超过阈值时主动释放冷数据 |

### 3.2 AI Loop 逻辑流程

所有 Agent 模式共享以下基础流程：

1. **理解** — Retriever 检索上下文 → 模型分析 → 生成需求摘要
2. **计划** — PlanGenerator → 生成 Plan 文档或执行计划
3. **确认** — Ask before edits 模式需要用户确认；Auto 模式自动确认（可配置）
4. **执行** — CodeEditor 应用补丁（dry-run → apply）→ DiffViewer 展示变更 → SandboxExecutor 执行命令 → TestRunner 运行测试 → LinterAnalyzer 检查问题
5. **提交** — GitManager 提交或生成 PR 草稿
6. **记忆更新** — MemoryCompressor → 写入长期记忆

### 3.3 长期记忆逻辑

- **数据结构**：事实记忆、交互记忆、行为记忆、计划记忆（详见 [4.3 Schema 设计](#43-数据库-schema-设计)）
- **存储**：SQLite + 文件系统 + FAISS 向量索引
- **压缩策略**：定期聚合相似条目，生成摘要；版本链追踪压缩来源
- **检索策略**：语义相似度（FAISS）+ 时间衰减权重 + 重要性加权
- **隐私**：AES-256-GCM 加密敏感记忆，密钥由用户持有
- **审查界面**：可按类型 / 时间 / 重要性浏览，查看明文、编辑、删除、导出

### 3.4 权限模型

| 级别 | 范围 | 示例 | 默认行为 |
|------|------|------|----------|
| **read-only** | 只读文件系统 | 列目录、读文件 | 静默允许 |
| **write-project** | 项目内写入 | 修改代码、创建文件 | Ask 模式需确认，Auto 模式静默 |

### 3.5 错误处理与降级策略

#### 3.5.1 错误分类

```
错误严重度金字塔：

  ┌─────────────┐
  │  Fatal      │ 进程无法继续，需立即终止并上报
  │  立即终止    │ 示例：数据库损坏无法恢复、沙箱逃逸检测
  ├─────────────┤
  │  Recoverable│ 当前操作失败，但系统可继续运行
  │  操作回滚    │ 示例：LLM 超时、文件写入冲突、OOM
  ├─────────────┤
  │  Degraded   │ 成功但非最优，可降级继续
  │  降级运行    │ 示例：FAISS 不可用 → 回退全文搜索
  └─────────────┘
```

#### 3.5.2 各子系统错误处理矩阵

| 子系统 | 典型错误 | 严重度 | 处理策略 | 用户感知 |
|--------|---------|--------|---------|----------|
| **LLM 调用** | 超时（> 30s） | Recoverable | 指数退避重试 3 次（1s/2s/4s），仍失败则提示切换模型 | "模型响应超时，已重试 3 次。建议切换至其他模型或稍后重试。[切换] [重试]" |
| **LLM 调用** | 4xx 错误（Bad Request） | Recoverable | 截断上下文至上一轮，重试 1 次 | "请求格式错误，已自动调整。如持续出现请反馈。[查看详情]" |
| **LLM 调用** | 5xx / 连接拒绝 | Recoverable | 退避重试 3 次，仍失败 → 标记为 Degraded | "服务端异常 (502)，已自动重试…" |
| **LLM 调用** | Rate Limit (429) | Recoverable | 读取 Retry-After 头，等待后重试 | "请求频率限制，将在 N 秒后自动重试。[立即重试]" |
| **LLM 调用** | 输出格式不合法（JSON 解析失败） | Recoverable | 重放原始 prompt + 格式错误提示（最多 2 次） | 透明（自动修复） |
| **文件系统** | 权限拒绝（EACCES） | Recoverable | 提示用户授予权限或跳过该文件 | "无法访问 X，请检查文件权限。[授予权限] [跳过]" |
| **文件系统** | 文件被外部修改（冲突） | Recoverable | diff 应用前检查文件 hash，冲突时提示用户选择版本 | "X 文件在外部被修改，与即将应用的补丁冲突。[保留我的] [保留外部] [手动合并]" |
| **文件系统** | 磁盘空间不足 | Recoverable | 暂停写入操作，弹出清理向导 | "磁盘空间不足 (< 100MB)，部分功能暂停。" |
| **Git** | 分支冲突 / rebase 中断 | Recoverable | 暂停 AI 操作，展示当前 Git 状态，提供回滚选项 | "Git 冲突检测，请先手动解决。当前操作已暂存。[查看状态] [回滚]" |
| **Git** | 未跟踪文件覆盖风险 | Recoverable | 先 git stash 再操作 | "检测到未跟踪文件，已自动暂存 (stash)。" |
| **FAISS** | 索引损坏 | Degraded | 回退到 SQLite 全文搜索（LIKE），后台重建索引 | "语义搜索暂时不可用，已切换为关键词搜索。索引正在后台重建。" |
| **FAISS** | OOM（内存不足建索引） | Degraded | 减小索引规模（仅保留 importance > 0.5 的条目），或回退 SQLite | 透明 + 通知："部分历史记忆暂不可搜索，系统正在优化。" |
| **Sandbox** | 命令执行超时（> 120s） | Recoverable | 发送 SIGTERM，5s 后 SIGKILL，返回部分输出 | "命令执行超时 (120s)，已终止。[查看输出] [增加超时] [重试]" |
| **Sandbox** | 可疑命令检测（`rm -rf /`、`curl | sh` 等） | Recoverable | 拦截并弹确认，用户确认后仍不执行高危模式 | "命令含潜在危险操作: `rm -rf /`。已被拦截。[编辑命令] [强制执行]" |
| **IPC** | 前端-Rust 通信中断 | Fatal | 尝试重建通道，失败后提示重启 | "内部通信异常，建议保存并重启应用。[重启] [保存日志]" |
| **数据库** | SQLite 锁定（SQLITE_BUSY） | Recoverable | 等待最多 5s（WAL 模式下极少发生），超时返回错误 | 透明（自动等待） |

#### 3.5.3 降级模式总览

BoschCode 定义三种全局运行模式：

| 模式 | 触发条件 | 行为 | 指示器 |
|------|---------|------|--------|
| **Full** | 所有子系统正常 | 全部功能可用 | 无 |
| **Degraded** | FAISS / Linter / 远程 LLM 不可用 | 禁用受影响功能，核心聊天和文件编辑仍可用 | 状态栏黄色图标 + 降级项灰显 |
| **Offline** | 网络断开 + 无本地模型 | 仅浏览文件树和会话历史，禁止执行和 AI 调用 | 状态栏红色图标 + 所有 AI 功能禁用 |

降级检查流程（每个操作前）：

```
操作请求
  │
  ├─→ 检查依赖子系统状态
  │     ├─ Full → 执行
  │     ├─ Degraded + 操作兼容 → 执行（记录告警日志）
  │     └─ Degraded + 操作不兼容 → 返回错误 + 降级提示
  │     └─ Offline → 返回错误（"此功能需要网络连接或本地模型"）
```

降级恢复：系统每 30s 探测不可用服务（轻量 health check），一旦恢复自动切回 Full 模式并推送通知。

#### 3.5.4 Crash Recovery 流程

```
应用崩溃
  │
  ▼
下次启动 → 检查 recovery/ 目录
  │
  ├─ 存在 recovery 文件 → 弹出恢复对话框:
  │   ┌──────────────────────────────────┐
  │   │ ⚠ 检测到上次非正常退出             │
  │   │                                  │
  │   │ 最后会话: "修复 login bug"        │
  │   │ 未保存消息: 3 条                  │
  │   │ 未应用变更: 2 个文件              │
  │   │                                  │
  │   │ [恢复会话]  [丢弃]  [查看详情]     │
  │   └──────────────────────────────────┘
  │
  └─ 无 recovery 文件 → 正常启动
```

### 4.1 技术选型结论

经过对比分析，选定以下技术栈：

| 层 | 技术 | 选型理由 |
|----|------|----------|
| **桌面壳** | Tauri v2 | 包体 < 5MB，内存占用低，Rust 原生系统调用 |
| **核心服务** | Rust | 与 Tauri 同进程零开销 IPC；无 GC，适合长期驻留；天然并发安全 |
| **前端 UI** | React 18 + TypeScript | 生态成熟，社区资源丰富，开发效率高 |
| **编辑器** | Monaco Editor | VS Code 同款内核，diff 渲染原生支持 |
| **状态管理** | Zustand | 轻量（< 1KB），API 简洁，TypeScript 友好 |
| **UI 样式** | Tailwind CSS | 原子化，主题切换方便，构建体积小 |
| **数据库** | SQLite (rusqlite) | 零配置，嵌入式，与 Rust 生态集成好 |
| **向量索引** | FAISS C API (faiss-sys) | Rust 直接绑定，无需子进程或 Python 桥接 |
| **IPC** | Tauri invoke + event | 前端调 Rust 用 invoke，Rust 推前端用 event |
| **Git 操作** | git2 (libgit2 Rust binding) | 纯 Rust 绑定，无需外部 Git CLI |
| **命令沙箱** | 自定义 sandbox crate | 基于 OS 级进程隔离 + 目录白名单 |
| **加密** | AES-256-GCM (ring crate) | 纯 Rust 实现，无外部依赖 |
| **测试框架** | Rust: cargo test / 前端: Vitest + Playwright | 标准方案 |

#### 备选方案对比

| 对比维度 | 选定方案 (Tauri + Rust) | 备选方案 (Electron + Node.js) |
|----------|------------------------|-------------------------------|
| 安装包体积 | ~8MB | ~150MB |
| 内存占用（空闲） | ~80MB | ~200MB |
| 文件遍历（10 万文件） | ~0.5s | ~3s |
| FAISS 集成 | 原生绑定 | 需 native addon 或子进程 Python |
| 开发效率 | Rust 学习曲线 | JS 全栈，上手快 |
| 社区生态 | 快速增长 | 极其成熟 |

> **结论**：当团队有 1 名以上 Rust 经验成员时选 Tauri；否则 MVP 阶段可先 Electron + Node.js，将性能热点（FAISS、大文件索引）用 Rust native addon 补充，后续逐步迁移。

#### 4.3.4 长期记忆

```sql
CREATE TABLE memories (
    id              TEXT PRIMARY KEY,
    project_id      TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    type            TEXT NOT NULL CHECK(type IN ('fact','interaction','behavior','plan')),

    -- 内容
    content         TEXT NOT NULL,         -- 自然语言原文
    summary         TEXT,                  -- 压缩后的摘要（高版本覆盖低版本）
    embedding       BLOB,                  -- float32 向量（FAISS 主存，SQLite 存副本）

    -- 元数据
    source_session_id TEXT REFERENCES sessions(id),
    importance      REAL NOT NULL DEFAULT 0.5, -- 0-1 权重
    access_count    INTEGER DEFAULT 0,
    last_accessed_at TEXT,

    -- 压缩与生命周期
    version         INTEGER DEFAULT 1,     -- 压缩版本号，每次压缩 +1
    compressed_from TEXT,                  -- JSON: 被合并的源记忆 ID 列表
    expires_at      TEXT,                  -- NULL = 永不过期

    -- 隐私
    encrypted       INTEGER NOT NULL DEFAULT 0, -- 是否加密存储

    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL
);

-- 记忆关联（知识图谱边）
CREATE TABLE memory_links (
    source_id   TEXT NOT NULL REFERENCES memories(id) ON DELETE CASCADE,
    target_id   TEXT NOT NULL REFERENCES memories(id) ON DELETE CASCADE,
    relation    TEXT NOT NULL,             -- related_to | depends_on | contradicts | extends
    weight      REAL DEFAULT 1.0,
    PRIMARY KEY (source_id, target_id, relation)
);

-- 向量索引元数据
CREATE TABLE vector_index_meta (
    id              TEXT PRIMARY KEY,
    project_id      TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    dimension       INTEGER NOT NULL,      -- 向量维度（由 embedding 模型决定）
    index_path      TEXT NOT NULL,         -- FAISS 索引文件路径
    entry_count     INTEGER DEFAULT 0,
    last_rebuilt_at TEXT,
    UNIQUE(project_id)
);

CREATE INDEX idx_memories_project_type ON memories(project_id, type);
CREATE INDEX idx_memories_importance ON memories(project_id, importance DESC);
CREATE INDEX idx_memories_accessed ON memories(project_id, last_accessed_at DESC);
```

## 5 开发步骤

### 阶段 0：技术 POC（0–2 周）

**目标**：验证核心选型可行，锁定技术栈。POC 只验证风险最高的假设，不写产品代码。

#### POC-1: Tauri v2 + React IPC 通信

| 项 | 内容 |
|----|------|
| **验证目标** | Tauri invoke 通信延迟是否满足 UI 交互要求 |
| **方法** | 搭建 Tauri v2 + React 最小骨架；构造 3 种 IPC 场景并测量 |
| **场景 A** | 调用 Rust 端读取项目目录树（5000 文件），测量 invoke 往返延迟 |
| **场景 B** | Rust 端流式推送 LLM token 到前端（event 机制），测量单 token 送达延迟 |
| **场景 C** | 前端连续调用 100 次 Rust 函数，测量总耗时与单次平均 |
| **通过标准** | 场景 A < 50ms；场景 B 单 token < 10ms；场景 C 平均 < 5ms |
| **失败回退** | 若 IPC 延迟超标 → 评估是否改用共享内存方案或降级为 Electron + contextBridge |
| **预期产出** | `poc/tauri-ipc/`：骨架项目 + 性能测试脚本 + 测量报告 |

#### POC-2: FAISS 向量索引集成

| 项 | 内容 |
|----|------|
| **验证目标** | faiss-sys 能否在三大平台编译通过，以及索引/查询性能是否达标 |
| **方法** | 使用 text-embeddings-infer (Rust) 生成 768 维向量，FAISS IndexFlatIP 索引 |
| **数据集** | 构造 1 万 / 5 万 / 10 万条模拟 memory embedding |
| **测量指标** | 索引构建时间、索引文件大小、Top-K 查询延迟 (K=5, 10, 20)、召回率 vs 暴力搜索 |
| **通过标准** | 1 万条索引 < 5s，查询 < 10ms (K=10)；10 万条查询 < 50ms；召回率 > 99% |
| **失败回退** | usearch (纯 Rust，无 C++ 编译负担) 或 pgvector (通过 PostgreSQL) |
| **预期产出** | `poc/faiss-bench/`：基准测试代码 + 三平台 CI 结果 + 对比报告 |

#### POC-3: Monaco Editor 集成

| 项 | 内容 |
|----|------|
| **验证目标** | Monaco 在 Tauri webview 中的加载速度和 diff 渲染性能 |
| **方法** | React 组件中加载 Monaco，测试语法高亮和 side-by-side diff 两种模式 |
| **场景 A** | 打开 1000 行 TypeScript 文件，测量从 onOpen 到可交互的时间 |
| **场景 B** | 渲染 5000 行 unified diff，测量渲染时间和滚动帧率 |
| **场景 C** | 连续快速切换 10 个文件，测量内存增长 |
| **通过标准** | A < 500ms；B 渲染 < 1s，滚动 30fps+；C 内存增长 < 50MB |
| **失败回退** | 若 diff 性能不足 → 大 diff 自动折叠，仅展示变更区域上下文；备选 CodeMirror 6 |
| **预期产出** | `poc/monaco-test/`：测试页面 + 性能数据 + 内存快照 |

#### POC-4: 大仓库文件树性能

| 项 | 内容 |
|----|------|
| **验证目标** | 虚拟滚动方案能否应对 10 万+ 文件的项目 |
| **方法** | 用 Rust 端实现文件树扫描（ignore crate 或 walkdir），前端用 @tanstack/react-virtual 渲染 |
| **测试数据** | 用脚本生成模拟仓库：10 万文件 / 1000 目录 / 深度 10 层 |
| **场景 A** | 冷启动首次扫描全量文件并发送到前端的时间 |
| **场景 B** | 展开深度嵌套目录 (深度 8) 的延迟 |
| **场景 C** | 文件监听 (notify crate) 下新增/删除文件的更新延迟 |
| **通过标准** | A < 2s；B < 100ms；C 更新延迟 < 500ms |
| **失败回退** | 按需加载子目录（非预加载全量）；排除列表可配置 |
| **预期产出** | `poc/filetree/`：骨架 + 测试数据生成脚本 + 性能数据 |

#### POC-5: git2 (libgit2) 基本操作

| faiss-sys 编译/性能不达预期 | 向量检索方案受阻 | Phase 0 优先验证；备选：usearch (纯 Rust) |
| Tauri v2 移动端需求不匹配 | 若后期需要移动端 | Tauri v2 已支持 Android/iOS，风险较低 |
| LLM API 变更或不可用 | 核心功能依赖 | 适配层抽象接口，支持多后端切换 |
| 单人/小团队进度压力 | 排期延迟 | 每阶段有明确的 MVP 裁剪范围 |
| 大项目文件树性能 | 用户体验差 | 虚拟滚动 + 增量加载 + 黑名单过滤（node_modules/.git） |

## 7 Skill 插件接口规范

### 7.1 设计目标

- Skill 是一个独立的 TypeScript/JavaScript 模块，在**沙箱环境中运行**
- 用户从内置目录或注册表安装，安装前需显式授权权限
- AI 可调用 Skill 作为工具使用；用户也可通过 `/skill-name` 直接调用
- 每个 Skill 声明其所需权限、输入 Schema、输出 Schema

### 7.2 插件清单 (Skill Manifest)

### 7.4 Skill API（Rust trait 定义）

```rust
/// Skill 管理 trait
pub trait SkillManager {
    /// 安装 Skill（从注册表 URL 或本地路径）
    fn install(&self, source: SkillSource) -> Result<Skill, InstallError>;

    /// 卸载 Skill（可选是否删除数据）
    fn uninstall(&self, skill_id: &str, remove_data: bool) -> Result<(), UninstallError>;

    /// 列出所有已安装 Skill
    fn list(&self) -> Vec<SkillInfo>;

    /// 启用/禁用 Skill
    fn set_enabled(&self, skill_id: &str, enabled: bool) -> Result<(), Error>;

    /// 更新 Skill 到最新版本
    fn update(&self, skill_id: &str) -> Result<Skill, UpdateError>;
}

/// AI 工具调用 trait——Skill 暴露给 AI 的函数
pub trait SkillTool {
    /// 工具名称（AI 看到的名字）
    fn name(&self) -> &str;

    /// 工具描述（AI 用来判断何时调用）
    fn description(&self) -> &str;

    /// 参数 JSON Schema
    fn parameters(&self) -> serde_json::Value;

    /// 执行工具调用
    /// - `sandbox`: 受限的沙箱上下文（文件 IO、网络等通过此接口）
    /// - `args`: AI 传入的 JSON 参数
    fn execute(
        &self,
        sandbox: &dyn SandboxContext,
        args: serde_json::Value,
    ) -> Result<ToolOutput, ToolError>;
}

/// 沙箱上下文——Skill 只能通过此接口访问系统资源
pub trait SandboxContext {
    /// 读取项目文件（受权限 scope 限制）
    fn read_file(&self, path: &RelativePath) -> Result<String, SandboxError>;

    /// 写入项目文件（需 write 权限 + 在 scope 内）
    fn write_file(&self, path: &RelativePath, content: &str) -> Result<(), SandboxError>;

    /// 执行命令（需 shell 权限）
    fn exec(&self, cmd: &str, args: &[&str]) -> Result<ExecOutput, SandboxError>;

    /// HTTP 请求（需 network 权限 + 域名白名单匹配）
    fn fetch(&self, req: HttpRequest) -> Result<HttpResponse, SandboxError>;

    /// Git 操作（需 git 权限）
    fn git(&self, op: GitOp) -> Result<GitResult, SandboxError>;

    /// 记录日志
    fn log(&self, level: LogLevel, message: &str);
}
```

#### 8.1.2 Onboarding 触发条件

| 条件 | 行为 |
|------|------|
| 首次启动（无 `settings.json`） | 强制显示 Step 1-2；Step 3-4 可选跳过 |
| 已配置模型但无项目 | 启动后显示主页 + 空状态引导（"打开第一个项目"） |
| 正常用户 | 不显示任何引导，直接进入上次会话 |
| 用户手动触发 | 帮助菜单 → "重新运行引导"；或 `/onboarding` 命令 |

### 8.2 主题系统

#### 8.2.1 设计原则

- 使用 CSS 自定义属性（CSS Variables）实现主题切换，无需重渲染组件树
- 所有组件只引用语义 Token，不硬编码颜色
- 支持暗色 / 亮色两种内置主题，扩展点支持第三方主题

#### 8.2.2 主题 Token 层级

```
Layer 1: 基础色彩 (Primitive Tokens)
  定义原始色值，不直接使用
  --color-slate-50: #f8fafc;
  --color-slate-900: #0f172a;
  --color-blue-500: #3b82f6;
  --color-red-500: #ef4444;
  ...

Layer 2: 语义 Token (Semantic Tokens) ← 组件只引用这一层
  --bg-primary: var(--color-slate-50);           // 主背景
  --bg-secondary: var(--color-white);            // 卡片/面板背景
  --bg-tertiary: var(--color-slate-100);         // 悬停/选中
  --text-primary: var(--color-slate-900);        // 主文字
  --text-secondary: var(--color-slate-500);      // 辅助文字
  --text-link: var(--color-blue-600);            // 链接
  --border-primary: var(--color-slate-200);      // 边框
  --accent-primary: var(--color-blue-500);       // 主题色
  --accent-danger: var(--color-red-500);         // 危险操作
  --accent-success: var(--color-green-500);      // 成功
  --accent-warning: var(--color-amber-500);      // 警告
  --diff-added-bg: var(--color-green-100);       // diff 新增行
  --diff-removed-bg: var(--color-red-100);       // diff 删除行
  --syntax-keyword: var(--color-purple-500);     // 代码语法高亮
  --syntax-string: var(--color-green-600);
  --syntax-comment: var(--color-slate-400);
  ...

Layer 3: 组件 Token (Component Tokens) ← 可选，仅复杂组件使用
  --chat-bubble-user-bg: var(--bg-tertiary);
  --chat-bubble-ai-bg: transparent;
  --sidebar-width: 280px;
  --toolbar-height: 48px;
```

#### 8.2.3 主题切换实现

```typescript
// 主题定义 (themes.ts)
interface Theme {
  name: string;
  mode: 'light' | 'dark';
  tokens: Record<string, string>;  // CSS 变量 override
}

// 系统自动检测
const prefersDark = window.matchMedia('(prefers-color-scheme: dark)');

// 用户手选优先级 > 系统检测 > 默认亮色
// 值写入 settings.json → 所有窗口同步
```

CSS 变量切换：

```css
:root {
  /* 默认亮色 */
  --bg-primary: #f8fafc;
  --text-primary: #0f172a;
  /* ... 所有语义 Token */
}

:root[data-theme="dark"] {
  --bg-primary: #0f172a;
  --text-primary: #f1f5f9;
  /* ... */
}

/* 组件从不引用具体颜色 */
.message-content {
  color: var(--text-primary);
  background: var(--bg-secondary);
}
```

#### 8.2.4 扩展点

- 第三方主题通过 CSS 文件导入，覆盖语义 Token
- 用户可将自定义 Token 写入 `~/.boschcode/themes/my-theme.css`
- MVP 仅内置暗色 / 亮色，第三方主题支持排入 Phase 6

### 8.3 国际化 (i18n)

#### 8.3.1 架构选型：key-based, 编译时检查

```
locales/
├── en/
│   ├── common.json        # 共享字符串
│   ├── chat.json          # 聊天相关
│   ├── settings.json      # 设置页
│   ├── errors.json        # 错误提示
│   └── onboarding.json    # 引导流程
├── zh-CN/
│   ├── common.json
│   ├── chat.json
│   ├── settings.json
│   ├── errors.json
│   └── onboarding.json
└── schema.json            # JSON Schema 校验所有 locale 键一致
```

#### 8.3.2 翻译 Key 命名规范

```jsonc
// en/common.json
{
  "app.name": "BoschCode",
  "button.save": "Save",
  "button.cancel": "Cancel",
  "button.retry": "Retry",
  "label.loading": "Loading...",
  "label.empty": "Nothing here yet",
  "time.seconds": "{n}s",
  "time.minutes": "{n}m"
}

// en/chat.json
{
  "chat.input.placeholder": "Ask anything about your project...",
  "chat.mode.ask": "Assistant",
  "chat.mode.plan": "Plan",
  "chat.mode.edit": "Edit",
  "chat.mode.auto": "Auto",
  "chat.error.timeout": "Model response timed out. {retry_link}",
  "chat.error.rate_limit": "Rate limited. Retry in {n}s."
}
```

#### 8.3.3 React 端用法

```typescript
import { useTranslation } from '@/i18n';

function ChatInput() {
  const { t } = useTranslation('chat');
  return <textarea placeholder={t('chat.input.placeholder')} />;
}
```

编译时检查：CI 中运行 `locale-check` 脚本，验证所有语言的 key 完全一致（用 `schema.json` 作参考 Schema）。

#### 8.3.4 各阶段 i18n 范围

| 阶段 | 范围 | 语言 |
|------|------|------|
| Phase 0-2 | 硬编码英文 | 1 种 |
| Phase 3-5 | i18n 基础设施 + 英文 + 简体中文 | 2 种 |
| Phase 6+ | 社区贡献更多语言 | N 种 |

> **原则**：所有用户可见字符串必须在源码中以 key 形式引用，不可硬编码。Phase 0-2 期间允许只有 en locale，但 key 体系不变。

#### 8.3.5 Rust 端日志/错误消息

Rust 端不直接面向用户输出自然语言，仅输出结构化错误码和英文日志。前端负责将错误码映射为本地化文案。

```rust
// ❌ 不推荐：Rust 端硬编码用户可见文案
bail!("文件未找到: {}", path)

// ✅ 推荐：返回结构化错误码
Err(AppError::FileNotFound { path: path.clone() })
```

```jsonc
// 前端 errCode → 本地化文案映射
// en/errors.json
{
  "error.FILE_NOT_FOUND": "File not found: {path}",
  "error.PERMISSION_DENIED": "Permission denied: {path}",
  "error.SANDBOX_ESCAPE": "Command attempted to access restricted area",
  "error.LLM_TIMEOUT": "Model response timed out"
}
```
